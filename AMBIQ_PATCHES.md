# Ambiq patch queue for CMSIS-DSP

`main` of this fork tracks upstream `ARM-software/CMSIS-DSP` unchanged (currently `83a2d7bc`). Ambiq changes land on `ambiq/integration` through reviewed pull requests, one row each below. Every change preserves the upstream `arm_*` function signatures, instance types, and documented storage contracts except where a row says otherwise; each code change carries a regression under `Testing/Regression/` that passes on the patched source and fails on the unmodified upstream source, and documentation-only rows say so in their Regression cell. Upstream disposition for every row: deferred; nothing has been submitted to Arm. Every fork pull request adds its own row in its own branch, so this file is never a trailing change; the merger refreshes each branch from `ambiq/integration` before merging and resolves adjacent-row conflicts there.

Governing discussion: [AmbiqAI/helia-dsp#11](https://github.com/AmbiqAI/helia-dsp/issues/11) (design) and [AmbiqAI/helia-dsp#20](https://github.com/AmbiqAI/helia-dsp/issues/20) (migration). Evidence platform unless stated: Corstone-300 FVP 11.24.13 (Cortex-M55), Arm GNU 14.3.Rel1, `-O3 -ffast-math`, handwritten MVE enabled, MPU guard immediately after the buffer under test.

## Toolchain

Compiler policy for heliaDSP (production compiler, excluded versions) is stated in heliaDSP's `COMPATIBILITY.md`; this section records only which compilers executed the regression tests of this fork and with what result.

Arm GNU 14.3.Rel1, `-O3 -ffast-math`, Corstone-300 FVP 11.24.13: every regression in the rows above passes with the figures given in its Evidence cell.

ATfE 22.1.0 (2026-10-01, same FVP, handwritten Helium kernels, `clang --target=arm-none-eabihf -mcpu=cortex-m55 -mthumb -mfloat-abi=hard` at `-O2` and `-O3` with `-ffast-math -flax-vector-conversions -DDISABLEFLOAT16`, objects linked with Arm GNU 14.3.1): `mve_matvec_tail` 63/63; `mve_rfft_table_guards` 36/36; `mve_matvec_tail_fixed` 357/357. Each test's own runner compiles and links with one GNU toolchain and was not changed; the ATfE builds used the same sources and flags with a separate compile and link step.
